# Data-plane runtime measurement

This directory owns operational measurement for the long-running M1–M3 data plane. Formal competition benchmark evidence remains under `benchmarks/m1`, `benchmarks/m3`, and `benchmarks/competition`; this directory answers a different question: what the continuously running system is doing now and how much useful traffic it is producing.

The public runtime denominator begins at the versioned `monitoring_measurement.public_epoch` in `config/source-inventory.json`. Earlier rows remain available as bootstrap/corpus-prefill but never enter public live-throughput, live-latency, or source-health trend claims. Monitoring traffic counts only `acquisition_trigger=scheduled`; query-time, investigation, replay and promotion acquisition remain visible under all-ingestion totals but cannot inflate monitoring throughput.

`current.json` is collected from PostgreSQL plus the active S3-compatible evidence namespace. It includes 1h/6h/24h/7d rolling windows, one-hour physical time series, eight-category time series, source health, poll success/yield, fresh/backfill/old-first-seen classification, fresh discovery/Knowledge latency, write amplification, document growth, source concentration and evidence-artifact integrity. Physical sources are assigned exactly one measurement category by the source inventory contract, so category traffic is additive even when one source contributes product semantics to several categories.

`current.md` is a renderer over the JSON snapshot and never owns numbers. Use `make data-plane-metrics` to collect a fresh snapshot and render it; `make data-plane-metrics-render` to render without touching runtime state; `make data-plane-metrics-check` to detect Markdown drift.

The presentation layer should prefer five chart families with fixed semantics. A stacked hourly **Fresh / Backfill / other first-seen** chart shows whether the system is watching the present or filling historical corpus. A **Fresh event → Knowledge p50/p95 + ≤15m/≤1h/≤6h** chart shows timeliness. A **source health / run success / queue p95 / execution p95** chart shows operational stability. A **Observation → KnowledgeRevision → canonical writes → chunks → Evidence bytes** funnel shows data-plane conversion and write amplification. A **fresh contributing sources/categories + top-1/top-5 share** chart shows whether live traffic is genuinely multi-source instead of being dominated by one feed.

Window choice follows source cadence rather than forcing every category onto one clock. Vulnerability, development, independent research and incident signals are primarily displayed at 1h/6h/24h. Academic, vendor research and normative knowledge are primarily displayed at 24h/7d; arXiv is intentionally polled once per day. Assets are query-time and are excluded from scheduled-monitoring throughput while remaining part of product coverage and all-ingestion metrics.
