# Visual direction and image generation

## Current interface direction — 2026-10-14

The current product pairs a continuous charcoal application shell with dark World/Ask surfaces, cool-white Intelligence/Workspace canvases, cobalt controls and saturated Phosphor icon tiles. The generated illustrations are archived and are not mounted in current routes. Ask keeps the same dark theme from its welcome state through saved answers and audit/evidence dialogs. World remains a dark source scene; Intelligence and Workspace retain light content surfaces. Functional UI remains React/Radix/Phosphor; artwork supplies no data or control semantics.

The built-in imagegen service generated a transparent night reading still life and a matching book-only service ornament in two calls. The exact prompts are `night-reading.prompt.txt` and `night-reading-detail.prompt.txt`. Archived, alpha-preserving WebP assets live in `public/art`; the full-size originals remain local generation artifacts. No named Image 2.5 model is claimed. The old eye character, optical slides, hand-drawn paper and large rain-window concept are retired.

The same-day follow-up trialed a transparent four-quadrant shortcut atlas from `workspace-shortcuts.prompt.txt`. It was rejected on 2026-10-14 for looking like game inventory pasted into a software interface; the public asset and runtime references have been removed. One built-in imagegen call produced the draft, without an exposed model identifier. See the [artwork archive](../../public/art/README.md).

The material pass keeps a narrow highlight on primary cobalt actions and uses matte secondary controls with short contact shadows. Round direction indicators remain decorative. World improves COBE's surface and continent visibility without adding markers or fabricated edges; Intelligence strengthens the selected channel and uses a Radix radio menu for the existing time range; Workspace removes diagonal template decoration. These are appearance changes with the existing information structure and data contracts.

## Previous exploration

The four `*.prompt.txt` files preserve the exact prompts from the approved visual plan. The requested API model was `gpt-image-2.5-sunburst`, with `quality=high`, a 1536×1024 opaque direction sheet and three 1024×1024 transparent WebP assets. The bundled imagegen CLI dry-run accepted these parameters. Live calls on 2026-10-12 all failed with `model_not_found`: this machine's configured distributor channel had no route for that model. The CLI wrote no images.

The built-in imagegen service produced a direction comparison and draft cutouts. The direction sheet (`direction-available-model.webp`) and instrument (`world-generated-unused.webp`) remain design artifacts, not runtime assets: the sheet is too generic, and placing a second mechanical globe behind the actual source map would dilute the evidence-led scene. The first Ask cutout was also rejected for its generic spherical robot shape. A revised, asymmetrical folded-cloak assistant became the welcome-state asset; its final prompt is in `ask-selected.prompt.txt`. The small optical-slide ornament became the Workspace services accent. These are **not claimed to be Image 2.5 outputs**.

The React interface owns its typography, layout, controls, graph and data states. Generated images do not contain metrics, edges, source labels or UI controls. The live World uses COBE as environmental depth; source nodes and provenance links remain native elements derived from recorded material. The direction sheet is a comparison artifact only and must not be rendered as a screenshot in the product.

The approved design follows a cool-white reading surface, deep-navy World stage and cobalt interaction language. The first screen has one main action: choose a source in World, open a feed item in Intelligence, ask a question in Ask, or resume work in Workspace. Detail is revealed in the source inspector, dossier, evidence dialog or task view.

2026-10-14: the book/lamp and shortcut stationery concepts were withdrawn from the live UI after whole-page comparison showed a mismatch with the software surfaces. `workspace-shortcuts.prompt.txt` is a rejected exploration, not the current visual specification. Interface components now take priority over decorative generation.
